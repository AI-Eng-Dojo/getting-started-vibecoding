# 講師・メンター用進行ガイド

参加者には配布しない。運営の判断基準と台本の要点をまとめる。

## 体制と機材

- 講師1名＋メンター（参加者8名につき1名目安）
- **講師・メンター機は全員Maxプラン必須**（救済ペア作業で枠を貸すため）
- 会場共有タイマー（後半の15分チェックポイント合図用）
- 配布する共有テンプレートリポジトリは無い。`vibecoding-0908`（前半2）・`myapp`（前半3〜後半）はいずれも**各参加者が当日その場でGitHub CLI（`gh` コマンド）を使って新規作成する**。事前準備0.4で `gh auth login` 済みであることが前提。`gh` コマンドがどうしても直らなかった参加者は、GitHub Web UIで手動作成→URLをClaude Codeに渡してcloneという代替手順に切り替えられる（01-part1・00-prep双方に記載）
- 置き場所は `~/github/`（Windowsは `C:\Users\⟨Windowsのユーザー名⟩\github\`）に統一する案内をしているが、**普段の置き場所がある参加者はそちらでも構わない任意扱い**。強制しない
- **手順上、リポジトリを作成した直後はまだ以前のフォルダを見ている。** 作成後に必ず「できたフォルダをVS Codeで開き直す」手順が挟まる（01-part1に明記）。ここを飛ばすと、エージェントスキルの保存先や以後のコミットが意図しない場所に散らばる。巡回時の最重要チェックポイント
- 提出フォーム3種: チェックポイント0（事前スクショ＋GitHubユーザー名＋`gh auth status` が通っている証跡）、チェックポイント3（`SKILL.md` 3つ＋`/tsumete` で質問が返る＋`CONTEXT.md`かADRのどちらかが実際に更新されている。**ADRが0本でも不合格ではない**）、宿題提出（後半前日までの `README.md`＋`TASKS.md`。書式は `templates/spec-readme.md`・`templates/tasks.md`）
- 救済版入り `starters/`（教材リポジトリ側。`starters/⟨題⟩/rescue/index.html`。配布URLは案内メールに記載）
- **講師の投影用環境は、参加者と同じまっさらな状態にする。** 自分用のエージェントスキル（`~/.claude/skills/`）や設定が入ったまま投影すると、同名の `tsumete` が候補に2つ並ぶ、別のエージェントスキルが勝手に動いて計画を立て始める、といった参加者の画面と違う動きになる。特に前半3の「`myapp` では `tsumete` が呼ばれない」は、講師機に同名のものがあると再現できない。投影専用のOSユーザーを用意するなど、既存の設定を読まない状態で臨む

## 設計思想（新任メンター向け）

1. **座学は最小限にする。** 説明したくなったら「それはコラムに書いてある」と言って先へ進む
2. **タイトル回収は後半10〜11（レビュー→公開）。** 「動いて終わり」ではなく「その先まで見る」ことの証明はここ。時間が押しても**後半10の①〜③（2軸レビュー・セキュリティレビュー）**は絶対に切らない。後半11のデプロイは丸ごと切ってよいが、**公開するならステップ1（`public/` 分離）を飛ばさせない**（飛ばすと仕様書ごと公開される）
3. **戻ることを正規の技術として教える。** 救済版の利用やバックアップ復帰を「失敗」の空気にしない。メンターの声かけは常に「戻って進むのは今日教えた技です」
4. **利用枠はProで完走できる設計。** ただし作法（まとめ指示・当日温存）が守られている前提。乱れたら個別に軌道修正する
5. **前半は「体験させる」、後半は「一人でやりきらせる」。** 前半のGrill Me系エージェントスキル自作でつまずいた参加者は、後半で必ず響く。前半3〜4の理解度は特に丁寧に見る

## 参加者構成と座席戦略（想定: 20名＝エンジニア10・非エンジニア（経営者・スタートアップ志望者など）10）

**テーブルは同質で分ける**（エンジニア島×2・非エンジニア島×2）。混成ペアにしない。

- 理由: 混成にするとエンジニアが隣のキーボードを「代わりに」触り始め、非エンジニアの手が止まる。本ワークショップの価値は自分の手で回した経験なので、これは最悪の失敗パターン
- メンター配分は非エンジニア島に厚く（非エンジニア島は5名に1人、エンジニア島は10名に1人目安）
- 交流は成果共有（後半13）で設計的に起こす。発表者はエンジニア・非エンジニアから最低1名ずつ選び、「同じプロセスで両方が形にできた」ことを見せるのがクロージングの説得力になる

進度差の吸収は🚀拡張ミッションが担う。エンジニアは本線を速く終えるので、拡張ミッション〔Eng〕（差分を読む・PRを出す・GitHub Actionsで自動デプロイ）へ誘導する。**本線の先回り（次のセクションを勝手に進める）は止める**——後続の説明が二度手間になるため。

> 注意: エンジニアはターン消費も速い。`/usage` 巡回では**エンジニア島の残量をむしろ警戒**する。
> 本ガイドが挙げる〔Eng〕3種（差分を読む・PRを出す・GitHub Actionsで自動デプロイ）はターン消費が少ない。ただし02-part2の「`/goal`で自走させる」「`prototype` で試作を作る」・01-part1の「もう1個作る」「メールの返信漏れを探す」は消費が大きいので、残量が細い参加者には振らない。

## オンライン開催の運営

会場開催を前提にした上の座席戦略は、オンライン（Discordなどの音声チャンネル）では次のように読み替える。

- **詰まった人は、声かチャットで申告してもらう。** 講師は全体を止めず、メンターが個別の音声チャンネルに移って画面共有で対応する。「自分の環境だけかもしれないから言わない」を防ぐため、冒頭で「詰まって申告してもらうのがメンターの仕事」と明言する
- **講師が待つのは、全員に共通する手順（リポジトリ作成など）で遅れが出たときだけ。** 待つ間は、下の待ち時間ネタから教材とつながるものを話す。「本編と関係ない話」で埋めない
- **合流したかは、個別チャンネルから戻ったメンターが講師に口頭で伝える。** 戻ってきた参加者に「どこまで進んだか」を講師から確認し、次の手順に移る
- **呼び方は「メンター」に揃える。** 教材も本ガイドもメンターで書いているので、当日の口頭でも言い換えない
- 後半の15分チェックポイントの合図は、会場タイマーの代わりに画面共有にタイマーを出し、チャットでも一言流す

## 待ち時間マイクロ解説ネタ集（コスト・ゼロの座学枠）

参加者は生成待ちで合計アイドル時間が出る。ハンズオン中、会場全体が「待ち」に入った瞬間に1枚スライドで挟む。**1本90秒以内・手を動かし始めた人がいたら即打ち切り**が鉄則。

| # | ネタ | 差し込みどころ | 要点 |
|---|---|---|---|
| W1 | いまClaudeは何をしているか | 前半①の最初の生成待ち | 指示→計画→ファイル操作→確認のループを回している。画面のツール実行表示の読み方 |
| W2 | 権限プロンプトの裏側 | 前半①で権限質問が出た頃 | **参加者テキストに掲載済み**（01-part1「『許可しますか?』と聞かれたら」）。今日はAuto Modeなので確認自体が少ないことが前提。口頭では「出たときは、AIが判断を委ねてきたサイン。2番は記憶される」の一点だけ補強する |
| W3 | まとめ指示が効く本当の理由 | 前半①のまとめ指示後 | ターン数節約だけでなく、方向性が一度に伝わるので手戻りが減る |
| W4 | エージェントスキルはなぜ効くのか | 前半②のtsumete作成中（ハンズオン①） | プロンプトは消えるが、保存した作法は残る。「毎回言っていること」を資産化する発想 |
| W5 | descriptionが呼ばれる/呼ばれないの分かれ目 | 前半②のtsumete動作確認時（ハンズオン①） | Claudeはdescriptionだけを見て使うか判断している。**症状別の直し方は参加者テキストの表（前半4・ハンズオン③）にあるので、そちらを見させる**。口頭は「自分が実際に打つ言葉をdescriptionに入れる」の一点 |
| W6 | 利用枠の仕組み | 後半開始直後の `/usage` 時 | 5時間ウィンドウ＋週次の二重構造。まとめ指示が枠の節約にもなっている |
| W7 | 「幻覚したgreen」実例 | 後半⑥の中盤の生成待ち | 「できました」と言って確認していなかった実例を1枚見せる。10の伏線 |
| W8 | エージェントスキルをチームに配るという発想 | 前半④の待ち | 個人の作法をリポジトリに入れるとチームの標準になる。拡張ミッションへの布石 |
| W9 | なぜHooksは確実に動くのか | 前半④のHook設定中 | エージェントスキルはAIが「使うか」を毎回判断するが、Hooksはイベント条件に合致すれば確認なしに必ず実行される。だからこそ登録は信頼できる内容だけに、という安全側の話に必ずつなげる |
| W10 | `CLAUDE.md` は毎回読まれる | 前半①でリポジトリ作成に遅れが出て、全体が待つとき | 宿題（前半6）で `myapp` に置く `CLAUDE.md` の予告。会話を始めるたびに丸ごと読まれるので、長くするほど毎回のコンテキストを圧迫する。フロントエンドとバックエンドが同居するリポジトリなら、片方の開発ルールをもう片方の人にまで毎回読ませない工夫が要る。詳しくはコラム★3へ誘導する |

運用メモ: 全部やる必要はない。**W2・W3・W7は必須**（安全・作法・検証の3本柱）、残りは会場の待ちの発生に合わせて取捨。

## 事前準備期間の運営

- チェックポイント0の提出状況を前日夜に集計。未提出者には個別連絡＋当日開始前のサポートタイム招集
- 提出スクショで環境の偏り（VS Code拡張／CLI、OS）を把握し、メンター配置に反映
- **CLIも全員が事前に導入する。** 00-prep.md 0.2の5に従い、ターミナルで `claude --version` の表示と `claude` の起動を確認させる。拡張に同梱されるCLIとは別に、ターミナル用の導入が必要。WindowsではPowerShellを選ばせる。通常の操作は引き続きVS Code拡張で進める
- **チェックポイント0で `gh auth status` の実行結果（スクリーンショットでよい）を提出させ、前日夜に全員分そろっているか確認する。** `gh` コマンド未認証のまま当日を迎えると、ハンズオン①冒頭の `gh repo create` で全員が止まる。未提出・未認証者は当日朝のサポートタイムで潰す
- **`gh` コマンドがどうしても使えない人は、GitHub web UIの「New repository」から手動作成し、Claude Codeに `git clone` してもらう代替手順がある**（00-prep.md 0.4に記載）。前日夜の確認で `gh auth status` が通っていない人には、この代替手順も案内しておく
- **Windows版拡張の起動条件は[検証メモ](windows-extension-verification.md)を参照する。**
  2026-09-08のCIでは、Windows Server 2025で外部Node.jsをPATHから除外し、外部 `node.exe` を起動せずに、検証した版の拡張でログイン画面まで表示できた。
  物理Windows 10/11と認証後の動作は未検証。
  講座では後半11の `npx wrangler` による公開と後半12のBacklog連携に使うため、引き続き全OSでNode.jsを導入する。
- **Windowsで、後半7の見本展開コマンド（PowerShell版: `curl.exe` で `main.zip` を保存して `tar -xf --strip-components=4`）が通ることを開催前に1回確認する。** macOS版（`curl | tar -xz`）は2026-09-11に main に対して動作確認済み。Windows版は同じ `tar`（bsdtar）がzipを展開できる前提で書いており未検証。通らなければ、本文の「手で写す」（ZIPを手で展開）へ誘導する
- **VS Code拡張で `/context` の Memory files に `myapp` の `CLAUDE.md` が出ることを開催前に1回確認する。** `docs/01-part1.md` 前半6は、宿題で置いた `CLAUDE.md` の読み込み確認に `/context` を使わせている。根拠は公式のメモリのページ（英語版。「読み込みの確認は `/context` の Memory files で行う。`/memory` は未作成のファイルも候補として並べる」、2026-09-08確認。日本語版は古く `/memory` で確認すると書いてある）。拡張のUI上での見え方は未検証。出なかった場合の手当て（Claude Codeを終了して開き直す）は本文に入れてある
- **Backlog MCPのバージョンを開催前に確認する。** `docs/02-part2.md` は `backlog-mcp-server@0.18.0` を固定で指定している（2026-08-30 時点の最新）。開催前に、その版が現在も取得できること・想定どおり動くことを確認し、必要なら番号を更新する。**バージョンを外して最新追従にしないこと**——当日何が動くか分からなくなる
- **新しく作ったCloudflareアカウントで、後半11を開催前に1回通す。** 公開の手段は `wrangler` だけになった。作ったばかりのアカウントでは、`wrangler login` の途中の「Sign in with Google」からログイン画面へ戻れるか、初回デプロイでサブドメインの自動登録に失敗したとき、本文のプロンプトどおりClaudeが止まってURLを示すか、そのURLの画面で名前を登録できるかが未検証。自動登録の挙動は `wrangler` 4.131.2 のソースで確認した（アカウントにworkers.devのサブドメインが無く、Claude Codeの中で動いていると、確認を出さずに `package.json` の `name` かフォルダ名、つまり全員 `myapp` で登録しようとして、名前が使えないエラーで止まる）。`login` → `whoami` → `deploy` まで通し、`.wrangler/` ができていればコミット対象に入っていないことも `git status` で確かめる（`node_modules/` があるとキャッシュはそちらに置かれ、`.wrangler/` はできない）
- **救済版は開催前に中身を見直す。** `main` 上の `starters/⟨題⟩/rescue/index.html` が実体で、**Gitタグは使わない**（タグ名と文書中のURLを人手で同期する方式は一度壊れた実績があるため）。開催前に各お題を実際に完成まで作り込んで差し替え、`.github/workflows/link-check.yml` が緑であることを確認する
- **拡張が起動しない系のトラブルは3段階で切り分ける**（00-prep.md 0.2に対処法を記載済みだが、提出スクショや当日の様子で見落としが疑われたら能動的に確認する）
  - **最初に見るのはVS Codeのバージョン（1.94.0以上か）**（[公式の拡張要件](https://code.claude.com/docs/en/vs-code#prerequisites)）。古ければ更新させる（00-prep.md 0.2の2）
  - Claude Code拡張を更新し、VS Codeを再起動させる（[公式のトラブル対処](https://code.claude.com/docs/en/vs-code#fix-common-issues)）
  - 解消しなければ、エラー文と画面を残してCLI版を試す。VS Codeのターミナルで、事前導入した `claude` を起動する。ログインを求められたら案内に従わせる。`claude` が見つからない場合は00-prep.md 0.2の5で導入とPATH設定を確認し、VS Codeを再起動して `claude --version` を再確認する。**講座の作業はCLI版でも進められる。** メンター側もこの順序と切り替え手順を把握しておく

## 前半の進行キュー

| セクション | 講師の要点 | メンターの動き |
|---|---|---|
| 1. オープニング | 今日の全体地図（前半→宿題→後半）を映しっぱなしにする。最後に**`/help` を投影で1回見せてから、全員で `/status` → `/model sonnet` → `/effort medium` → `/usage` を叩かせる**。前半・後半共通の推奨は **Sonnet × medium** と口頭でも伝える。**Maxプランの既定はOpusなので、Maxの人ほど `/model sonnet` を忘れやすい**と一言添える。バイブコーディングの説明では「コードが読める人も手で直さない。作るのはAI、品質を確かめるのは自分」を必ず言う | 巡回してモデルとeffortの設定で固まっている人を拾う。残量が少ない人を把握 |

| 拡張がTypeErrorなどでクラッシュする | エラー文と画面を残し、上の行と同じ順に確認する。直らなければVS Codeのターミナルで `claude` を起動する（見つからない場合は00-prep.md 0.2の5で導入とPATH設定を確認） |
| 全体的に応答が遅い（障害・混雑） | ハンズオンは待ち時間に言語化ワーク・仕様の見直しを前倒しする |
| 環境が完全に壊れた参加者 | **先にいまの状態をコミット＆プッシュ（またはファイルをコピー退避）させてから**、Claude Code Web版（ブラウザ実行）に切り替えて継続。自作エージェントスキルも `myapp` の `.claude/skills/` にあるので、プッシュ済みなら一緒に引き継がれる。プッシュしていなかった場合は `SKILL.md` の中身を貼り直させる |
| 後半9でプッシュが弾かれる（コミットは通るが push だけ失敗する） | `gh auth status` を確認させる。**未認証・別アカウントでログインしている人**→ブラウザでGitHubログインを通し直させる。**そもそも `myapp` を作れていない人**→ハンズオン②の手順に戻ってその場で作り直す（`gh` コマンドがだめならWeb UI手動作成＋clone） |
| エージェントスキルが作ったはずなのに呼ばれない・pushしたファイルが想定と違う場所にある | **リポジトリ作成直後にVS Codeを開き直していない可能性が高い。** Claude Codeがまだ1つ前のフォルダを見ている状態で作業を続けている。`~/github/vibecoding-0908`（または `myapp`）を直接開き直させる |
| アイデア乗り換えを始めた参加者 | 「メモして持ち帰る」に誘導。乗り換えは迷子の最大要因という理屈まで伝える |
| 宿題が未着手のまま後半に来た参加者 | 前半2〜3で作ったものを種に、後半7の時間で急いで1周させる。それでも決まらなければ [starters/](../starters/) のお題を仕様として仮採用させる |
| やることが20個ある参加者 | **減らさせない。** 後半8でMVPに絞り込ませ、残りは「持ち帰る分」へ移させる。詰めた量は持ち帰る資産だと伝える |
| 後半10で指摘が1本のリストで返ってくる | 「仕様どおりか」と「作法どおりか」の2つの見出しに分けて報告し直させる。**混ざったリストは、どれが重いか分からなくなる**というのがこのハンズオンの主題そのもの |
| 後半10④でセキュリティレビューを通しても、プッシュが止まり続ける | 原因は2つ。**(1) Hook Aが作った直後の印を消している。** 教材の古い版（Hook Aをプロンプトだけで作らせていた版）で登録した人に起きる。`/hooks` でHook Aの中身を確認させ、10④のプロンプトで `hooks/clear-security-reviewed.sh` を使う形に登録し直させる。Hookは起動時に読み込まれるので、登録し直したら**Claude Codeを開き直してから**、もう一度 `セキュリティレビューして` →プッシュ。**(2) レビューの後に `TASKS.md` などを書き換えた。** 「直さなかった指摘を書き足す」もファイルの書き換えなので、Hook Aが印を消すのは正常な動き。もう一度レビューを通させる |
| 後半11で `wrangler deploy` がHookに止められる | **正常な挙動。** `wrangler.jsonc` を書いた時点でHook Aが印を消しているため。`セキュリティレビューして` を通してからデプロイを頼み直させる |
| 後半12でBacklog MCPが接続できない | まず `node -v` を確認（事前準備0.2で全OS必須にしたが、未実施の人が残る可能性はある）。次に**`.env` を読み込んだのと同じターミナルタブで `claude` を起動し直しているか**を確認する（別タブで起動すると環境変数が引き継がれず、設定ファイルに `${BACKLOG_API_KEY}` が未展開のまま残って接続できない）。それでも通らなければ**Notionへ切り替えさせる。** APIキーの再発行を試す前にここを確認する |
