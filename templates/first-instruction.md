# 最初の指示テンプレート（後半9 ハンズオン⑥用）

後半9でコミット前のレビューフックを用意してから使います。
`TASKS.md` の「MVP」に並ぶ未着手の一件だけを進めます。

```text
TASKS.md の「MVP」の次のやることに取りかかります。その1件だけを実装してください。
- 実装を始める前に、その1件の完了定義をそのまま読み上げてください。
  書かれていない、または画面で判断できない場合は、実装せずに案を出してください
- 完了定義を満たすためだけのコードを書き、次の1件の機能を先に作らないでください
- 実装したら、どのファイルかURLを開き、何を操作し、どこを見ればよいかを短く伝えて止まってください。
  私が確認するまで、終わったと宣言しないでください
```

自分でブラウザを操作し、その一件と、これまで動いていた機能を確かめます。
同梱の `/code-review` はコードの不具合を探しますが、欲しかった体験かどうかは自分で判断します。

## 2つ目以降

完了定義を満たしたら、次を送ります。

```text
確認できました。TASKS.md の状態を「済」に更新してコミットしてから、
MVPの次の1件を同じ順で進めてください。
コミットがフックに止められたら、次へ進まずに、止められた理由を報告してください。
プッシュはしないでください。
```

コードレビューの指摘が届くまで待ち、直すものを選びます。
セキュリティレビューのCriticalとHighは、直すか該当機能を外してから、画面で確かめ直してコミットします。
プッシュは、後半10で未送信のコミット全体をセキュリティレビューしてから行います。

## 詰まったら

```text
⟨何を操作したか⟩をすると、⟨実際に起きたこと⟩になります。
完了定義のとおりに動くよう直してください。これまで動いていた機能も保ってください。
```

エラーメッセージや画面のスクリーンショットがあれば、そのまま添えます。
同じ一件が15分で終わらなければ、さらに小さく分けます。
自動テストも試したい人は、任意課題の [`tdd`](../skills/tdd/SKILL.md) を使えます。
