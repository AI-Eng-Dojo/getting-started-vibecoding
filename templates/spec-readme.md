# 仕様READMEワークシート（宿題用）

前半3で書いた[アイデアREADME](idea-readme.md)を、自作の `tsumete` で問い詰めたあとの書き出し先です。後半7にこの状態で持ってきてください。

**置き場所**: `myapp` のルート（`README.md`）。前半3で作ったREADMEを、そのまま育てます。

> **`CLAUDE.md` を再確認します。** 前半3で置いた `myapp/CLAUDE.md` に、次の条件があることを確認してから `/tsumete` を使います（見本は [CLAUDE.md.sample](CLAUDE.md.sample)）。
> 1. ブラウザだけで動く構成にする（HTMLファイル1つが基本）
> 2. ログイン・課金・外部サービス連携は今回やらない
> 3. 後半の実装時間で作りきれる規模まで削る

## 何を作るか（一言で）

```text
⟨                                          ⟩
```

## 誰が使うか

```text
⟨                                          ⟩
```

## どんな体験にしたいか

前半3でデモを触って気づいたことを引き継ぎ、操作と結果で確かめられる形にします。

```text
⟨どんな場面で、何をすると、どのように使えるか⟩
```

## できること（3〜5個）

**「自分が操作して、目で確認できること」**の形で書きます。ここがそのまま後半の実装タスクになります。

- 悪い例:「タスクを管理できる」（何ができたら完成か分からない）
- 良い例:「入力欄にタスク名を入れてEnterを押すと、下の一覧に追加される」

```text
1.
2.
3.
4.
5.
```

## 今回やらないこと

Grill Meの過程で出た「それは今回は作らない」を、捨てずにここへ書き写します。**1件ずつ、今回のスコープから外す理由も一行で。** 後半12で、その理由ごとNotionやBacklogへ渡ります。

```text
- ⟨今回は作らないもの⟩ — ⟨外す理由⟩
- ⟨今回は作らないもの⟩ — ⟨外す理由⟩
```

## データをどう扱うか

```text
□ 残さない（ページを閉じたら消えてよい）
□ ブラウザに保存する（閉じても残る） ← 今日はここまでが範囲
```

## 完成判定（何が動いていれば完成か）

後半10の通し確認と、[今日の完成判定](../docs/02-part2.md#-今日の完成判定)で、これを見て自己判定します。
同梱の `/code-review` はコードの正しさを点検するためのものです。仕様への適合は、このREADMEと画面の操作結果を照らして確認します。

```text
-
-
-
```
