# レビュー・プロンプトテンプレート（後半10 ハンズオン⑦用）

後半10で使う `code-review`・`security-review` スキルが**呼ばれなかったとき**の代替です。そのまま貼り付けて使えます。

> **本線はスキルです。** まず `コードレビューして` / `セキュリティレビューして` と頼み、起動しなかった場合だけ下を貼ります。ワークショップ後も、何かを実装するたびに使えます。

## ① 2軸コードレビュー（`code-review` の代替）

**この2つを1本のリストにまとめさせないこと**が肝心です。混ざると、どれが重いのか分からなくなります。

```text
実装したコードを、次の2つの軸で別々にレビューしてください。
1本のリストにまとめず、見出しを分けて報告してください。まだ直さないでください。

【軸1: 仕様どおりか】
README.md（無ければ TASKS.md）を仕様として、次を報告してください。
- 仕様にあるのに実装されていない・途中までのもの
- 仕様に無いのに実装されているもの（特に「今回やらないこと」に書いたもの）
- 実装されているが、仕様が求めているものと意味が違うもの
指摘ごとに、仕様の該当箇所を引用してください。

【軸2: 作法どおりか】
CLAUDE.md・CONTEXT.md の決めごとがあればそれを最優先で、無ければ次の観点で。
- 名前が意味を表していない
- 同じことが2箇所以上に書かれている
- 同じ判定が複数の場所に散らばっている
- 1つの仕様を変えるのに何箇所も直す必要がある
セキュリティは対象外です（②で別に見ます）。
```

指摘を読んでから、直すものだけを選んで指示します。

```text
仕様の1と2、作法の1を直してください。残りは今日は対象外にします。
```

```text
直さなかった指摘を、TASKS.md に「レビューで出た宿題」という見出しで書き足してください。
それぞれに、今日直さない理由を書いてください。
```

## ② セキュリティレビュー（`security-review` の代替）

**①で直したあとに実行してください。** 直したことで危なさの状態が変わっている可能性があります。

```text
実装したコードのセキュリティを、次の観点で上から順に確認してください。
重大度（高・中・低）を付けて、高い順に報告してください。まだ直さないでください。

1. 秘密情報（APIキー・パスワード・トークン）がコードに直接書かれていないか
2. ユーザーが入力した文字が、そのままHTMLとして画面に埋め込まれていないか
3. 文字列をそのまま実行していないか（eval など）
4. ブラウザに保存しているデータは、そこに置いてよいものか
5. 頼んでいない外部への通信が入っていないか
6. 外部リンクに rel="noopener" が付いているか
7. このファイルをそのまま他人に見せて困るものが残っていないか
8. 公開するフォルダに、公開してよいものだけが入っているか

最後に、確認したが問題がなかった観点も書いてください。
```

直したあと、直さなかったものは記録に残します。

```text
直さなかったセキュリティ指摘も、TASKS.md の「レビューで出た宿題」に書き足してください。
それぞれに重大度と、今日直さない理由を書いてください。
```

> **「できました」を鵜呑みにしない。** Claudeは実際には確認せず「できています」と答えてしまうことがあります。最後は必ず自分の目でレビュー結果と動作を確認してください。**あなたの確認が最終権限です。**
