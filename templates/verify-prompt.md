# 動作確認とレビューのプロンプト（後半9〜10用）

コードの不具合、仕様への適合、セキュリティを分けて確かめます。
同梱の `/code-review` と組み込みの `/security-review` を使い、同じ名前のエージェントスキルはコピーしません。

## 完成判定を通しで確認する

```text
README.md の完成判定と TASKS.md のMVPを読み、ブラウザでの確認手順を一覧にしてください。
どのファイルかURLを開き、何を入力してどのボタンを押し、何が見えればよいかを書いてください。
仕様にあるのに未実装のもの、仕様にないもの、意味が違うものも、仕様の該当箇所を添えて報告してください。
まだ直さないでください。
```

一覧に沿って自分で操作します。
見つけた違和感をまとめて伝え、修正後はすでに動いていた機能も確かめ直します。

## コードレビューの結果を受け取る

```text
/code-review
```

結果が届くまで待ちます。
現在のMVPに関わる不具合は直し、再利用や簡素化の提案は持ち帰りに回して構いません。
レビューは完了定義を満たしたかの判定を代わりに行うものではありません。

```text
指摘のうち⟨直す番号⟩を直してください。
残りは TASKS.md の「レビューで残した指摘」に、今回直さない理由つきで残してください。
```

## 初回プッシュ前のセキュリティレビュー

```text
/security-review
```

初回プッシュ前なら、リポジトリ作成時からの未送信コミット全体を確認できます。
既定ブランチを判定できないエラーが出たら、その内容を伝えて原因を確認させます。
CriticalとHighを解消してからプッシュします。
残した指摘には重大度と理由を書きます。

## コマンドやエージェントフックが使えないとき

`/code-review` が使えない場合は、次を使います。

```text
まだプッシュしていないコミットと未コミットの変更を、実装した会話とは別のサブエージェントでコードレビューしてください。
現在のMVPの動作に関わる不具合と、再利用や簡素化などの改善案を分けて報告してください。
指摘には場所と理由を添え、まだ修正しないでください。結果が届くまで待ってください。
```

セキュリティレビューを手動で行う場合は、次を使います。

コミット前の確認は `git diff HEAD` と除外対象ではない未追跡ファイル、プッシュ前の確認は未送信コミット全体を対象にします。
次の⟨⟩を置き換えて貼り付けます。

```text
⟨git diff HEAD と未追跡ファイル／まだプッシュしていないコミット全体⟩を、別のサブエージェントでセキュリティレビューしてください。
.claude/hooks/security-review-prompt.md から確認観点と重大度だけを使ってください。
対象範囲は上の指定に合わせ、フック用のokだけでなく、Critical、High、Medium、Lowの全指摘を報告してください。
まだ修正、コミット、プッシュはしないでください。
```

観点のファイルをまだ置いていない場合は、[配布する確認観点](../hooks/security-review-prompt.md) の内容を指示に添えます。
機械的なフックが動かない場合も、確認する対象と順番は変えません。
