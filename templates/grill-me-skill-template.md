# Grill Me系エージェントスキルの雛形（前半4の自作用）

前半4「Grill Me系エージェントスキルを自作する」で使う出発点です。前半4では `tsumetsume`・`ddd`・`tsumete` の3つを作りますが、この雛形は1つ目の `tsumetsume`（一問ずつ問い詰める部分）専用です。残り2つのサンプルは [docs/01-part1.md](../docs/01-part1.md) 本文にあります。

`tsumetsume` は中身を持つエージェントスキルなので、**`description` には「いつ使うか」を必ず書きます。** Claudeはそこを読んで自分で呼ぶかどうかを判断します。

そのまま使わず、⟨ ⟩の部分を自分の言葉で書き換えてから `SKILL.md` として保存してください。**丸写しでは、宿題・後半で自分が欲しい質問をしてくれません。**

```markdown
---
name: ⟨名前・英数字とハイフンのみ⟩
description: ⟨このエージェントスキルが何をするか、いつ使うべきかを一文で。Claudeはここだけを見て使うかどうか判断します⟩
---

# ⟨エージェントスキルのタイトル⟩

⟨ここから、質問の仕方そのものを指示として書きます。以下は書き方のヒントです⟩

- 一度に質問する数（1つずつか、まとめてか）
- 何について聞くか（誰が使うか／何ができれば完成か／どこまでの範囲を今回はやらないか、など）
- 事実確認（自分で調べられること）と、決定（ユーザーに委ねるべきこと）をどう区別するか
- どこまで厳しく・何往復くらい問い詰めるか
- 共通理解に到達したかを、どう確かめて問答を終えるか
```

<a id="最後に何を出力させるかを必ず書く"></a>

## 成果物の出力は入口の `tsumete` に書く

`tsumetsume` は質問の進め方を担当し、途中の用語や決定は `ddd` が記録します。
仕様と実装計画の書き出しは、二つを束ねる入口の `tsumete` に指示します。
以下は `tsumetsume` の本文には加えず、前半4で `tsumete` を更新するときに使ってください。

```text
最後に、次の2つを書き出してください。

1. 具体化された仕様を README.md に
   （何を作るか／誰が使うか／どんな体験にしたいか／できること／今回やらないこと〈理由も一行ずつ〉／完成判定）

2. 実装する順に「やること」の一覧を TASKS.md に
   - 「状態／やること／完了定義」の3列の表にし、状態はすべて「未」で始める
   - 1つのやることは15分以内で終わる大きさにする
   - それぞれに完了定義（画面のどこを見れば終わったと分かるか）を書く
   - 上から順にやれば、途中で止まっても動くものが残る順番にする
```

「途中で止まっても動くものが残る順番」に並べます。**印刷や仕上げを先にやると、時間切れのときに何も動きません。**

## 保存先

```
⟨プロジェクト⟩/.claude/skills/⟨エージェントスキルの名前⟩/SKILL.md   ← プロジェクトレベル（この講座ではこちら）
~/.claude/skills/⟨エージェントスキルの名前⟩/SKILL.md                ← ユーザーレベル（この講座では使わない）
```

自分でフォルダを掘る必要はありません。書いた中身をそのまま貼って、Claude Codeに保存させてください。

```text
次の内容を、このリポジトリ（myapp）の .claude/skills/⟨エージェントスキルの名前⟩/SKILL.md として保存してください。
フォルダが無ければ作ってください。

⟨ここに、自分で書いたSKILL.mdの中身をそのまま貼る⟩
```

この講座では、宿題も後半も `myapp` で作業するので、**プロジェクトレベル**（`myapp` の `.claude/skills/`）に置きます。別のプロジェクトでも使いたくなったら、そのプロジェクトの `.claude/skills/` にコピーしてください。

## 動作確認の手順

1. `myapp/.claude/skills/` に保存する。置き場所自体を初めて作ったときはClaude Codeを再起動する
2. 既存の置き場所に追加した内容はそのまま反映される。候補に出なければ `/reload-skills`、再起動の順に試す
3. `description` に書いた呼び出し方（例:「詰め詰め」）で呼んでみる
4. 質問を直したい場合は本文を変更し、`/clear` で旧版の本文が残る会話を切ってから試す

同じ名前のエージェントスキルがユーザーレベルにあると、そちらが優先されます。意図した版が動かない場合は、名前と保存先も確認してください。

## サンプル（詰め詰め）

書き方に迷ったら、この完成例を見てから自分の言葉で書き直してください。

```markdown
---
name: tsumetsume
description: 計画や仕様を実装前に徹底的に問い詰めて磨き上げる。実装前に計画を揺さぶりたいとき、「詰め詰め」と頼まれたときに使う。
---

# 詰め詰め

この計画のあらゆる側面について、共通理解に到達するまで徹底的にインタビューしてください。
質問は一度に一つだけにし、回答を受け取ってから次へ進んでください。
各質問には、あなたが推奨する回答も必ず添えてください。
調べれば分かる**事実**は質問せず自分で確認し、**決定**はユーザーに委ねてください。
```
