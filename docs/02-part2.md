# 後編（2時間）狙ったものに確実に仕上げる

後編のゴール: **前編④で「詰めて」を始めた自分のアイデアを、検証済みの完成品にして持ち帰ること。**

> 開始前の儀式（前編と同じ）: `/status` で残量確認。半分を切っている人は挙手してください。
> メンターが進め方（まとめ指示の徹底・メンター機ペア作業）を個別に調整します。

---

## 7. 「確実に」の正体（10分・今日最後の座学）

前編の終わりに触れたとおり、バイブコーディングの弱点は**迷子**です。典型的な失敗はこう進みます。

> ノリで機能を足す → だんだん指示が雑になる → どこかが壊れる → 直させると別の場所が壊れる → 何が「正解の状態」だったか自分でも分からなくなる → 終了

原因は能力でも運でもなく、**3つの不足**です。

| 不足 | 症状 | 処方 |
|---|---|---|
| 決めていない | 「もっと良く」を無限に繰り返す | 原則③の続き。**前編④で詰めた完成条件にないものは今日は作らない** |
| 確認がない | できたつもりで先に進み、後で崩壊 | 完成条件を1つ満たすたびに自分の目で確認 |
| 戻り先がない | 壊れた地点まで手探りで後退 | **15分ごとにチェックポイント**（動く状態を保存する） |

これから60分、この処方をそのまま運用します。タイマーは会場全体で共有します（15分ごとに合図が鳴ります）。

## 8. ハンズオン⑤ 自分のアイデアを作る（60分・メイン）

### 進め方

1. **開始（最初の5分）**: 前編④で「詰めて」を始めたフォルダをそのまま使います。詰めた結果（決まったこと・完成条件）をふまえて、実装の最初の指示を出します。テンプレはこれです（コピペ用: [templates/first-instruction.md](../templates/first-instruction.md)）:

```text
前編で「詰めて」で決めたことをふまえて、実装に入ります。

このアプリの完成条件は次の3つです。
1. ⟨完成条件1⟩
2. ⟨完成条件2⟩
3. ⟨完成条件3⟩

まず、完成条件1だけを満たす最小版を、1つのHTMLファイルで作ってください。
2と3はまだ作らないでください。
```

> ポイントは最後の2行です。**いきなり全部作らせない。** 最小版が動いてから積み上げるのが、動く状態を保ったまま進むということです。
> 完成条件が3つに固まっていない人は、ここで「詰めて」をもう2〜3問だけ回してから始めてください。

2. **15分ごとのチェックポイント運用**: 会場の合図が鳴ったら、手を止めて次を実行:
   - 今、アプリは動いているか? → 動いていれば**その状態を保存**（Gitが分かる人は `git commit`、分からない人はフォルダごと複製して `backup-1430` のような名前を付けるだけでOK）
   - 動いていなければ → **リカバリー3手**（貼る・戻す・小さくする）で動く状態に戻してから保存
   - 保存したら次の完成条件へ進む

3. **回し方は前編のリズムで**: 違和感は2〜3個まとめて1回で。画像で伝えられるものは画像で。

### 詰まったときのリカバリー3手

| 手 | いつ使う | どうやる |
|---|---|---|
| **① エラーをそのまま貼る** | 画面が真っ白・エラーが出た | エラーメッセージや画面のスクショを**説明せずそのまま**貼り、「動かなくなりました。直してください」 |
| **② ひとつ戻す** | 直る気配がない・どんどん悪化する | 「さっきの変更を取り消して、直前の動いていた状態に戻してください」。会話を巻き戻す機能やGitでも戻れます |
| **③ 小さく言い直す** | 欲張った指示が空中分解した | 5個頼んだなら「まず1個だけ」に分割してやり直す |

> 覚え方: **貼る・戻す・小さくする。** 詰まりの9割はこの3手で抜けられます。

### 詰まったときのエスカレーション順

1. リカバリー3手（貼る・戻す・小さくする）— まず自分で2回試す
2. 挙手 → メンターが巡回します
3. それでも詰まったら**救済ルート**: 直近のバックアップから再開。恥ずかしいことではありません。**「戻って進む」は正規の技術です**

### よくある divergence と対処

| 状況 | 対処 |
|---|---|
| 最初の完成条件が15分経っても動かない | 作ろうとしている範囲が大きすぎるサイン。メンターと一緒に小さく割る |
| 予定より早く完成条件を満たした | おめでとう。9を先取りして検証まで済ませ、その後「見た目をもう一段」へ |
| 途中でもっと良いアイデアを思いついた | **今日は乗り換えない。** メモして持ち帰る（乗り換えは迷子の最大要因） |
| 利用枠の上限に当たった | 挙手 → メンター機（Max）でペア作業に切り替え |

### ✅ チェックポイント5

完成条件のうち**2つ以上**が動いている状態で9へ。（全部揃っていなくても大丈夫です。仕上げの時間で追い込みます）

### 🚀 拡張ミッション⑤（完成条件を満たして時間が余った人向け・任意）

- まず9（仕上げと検証）を先取りして完了させる。そのうえで:
- 〔共通〕**4つ目の条件を足す**: 「今後やりたいこと」から1つ選び、今日の型（詰める→計画→最小版→確認）でもう一周。同じ型が2周目は倍速で回ることを体感する
- 〔Eng〕**計画→実装の2段で足す**: 4つ目の機能をプランモードで計画させ、計画を読んでから実装を許可する。バイブコーディングとスペック駆動（★コラム6）の中間地点
- 〔Eng〕**チェックポイントをGitに格上げ**: 15分保存をコミット運用にし、わざと1機能壊してから `git checkout`（または「この変更を取り消して」）で戻る訓練をしておく

## 9. ハンズオン⑥ 仕上げと検証（25分）

「確実にできあがった」と言い切るための締めの工程です。

### ステップ1: Claudeに検証させる（10分）

自分の目に加えて、Claude自身に完成条件をチェックさせます（コピペ用: [templates/verify-prompt.md](../templates/verify-prompt.md)）。

```text
このアプリの完成条件は次の3つです。
1. ⟨完成条件1⟩
2. ⟨完成条件2⟩
3. ⟨完成条件3⟩

それぞれについて、実際にどう確認したかを説明した上で、満たしているか判定してください。
満たしていないものがあれば、直してから再度確認してください。
```

> **「できました」を鵜呑みにしない。** Claudeは実際には確認せず「できています」と答えてしまうことがあります。
> 「どう確認したかを説明した上で」の一文がそれを防ぐ仕掛けです。
> 最後は必ず**あなたの目**で3条件を触って確認してください。あなたの確認が最終権限です。

### ステップ2: 見た目をもう一段（10分）

残り時間で、共有タイムに向けて磨きます。まとめ指示1回分だけ:

```text
発表用に見た目を仕上げてください。
1. アプリ名をタイトルとして目立つ場所に表示
2. 全体の配色とフォントを統一して、素人っぽさをなくす
3. スマホの画面幅でも崩れないように
```

### ステップ3: 公開前のセキュリティレビューとREADME（5分）

共有タイムで画面を見せる前に、前編②で作った2つ目のスキルを1回かけます。

```text
セキュリティレビューして
```

**「高」または「中」の指摘が出たら、直してから共有タイムに進んでください。** 今日のアプリは自分のPCの中だけで動きますが、この先これを人に渡すなら、渡す前にかけるのがこのスキルの本来の使い方です。

続けてREADMEを書かせます。

```text
このアプリのREADME.mdを作ってください。内容は:
- アプリ名と一言説明（詰めて決めたことをもとに）
- 使い方（開き方と操作手順）
- できること（完成条件3つをもとに）
- 今後やりたいこと(あれば)
```

### ✅ チェックポイント6（完成判定）

- [ ] 完成条件3つを**自分の目**で確認した
- [ ] Claudeの検証報告と自分の確認が一致した
- [ ] セキュリティレビューを1回かけ、「高」「中」の指摘が残っていない
- [ ] READMEがある

4つチェックが付いたら、それが「確実にできあがった」の定義です。

### 🚀 拡張ミッション⑥（完成判定後・任意）

- 〔共通〕**マイ検証テンプレを持ち帰る**: 9で使った検証プロンプトを `my-verify.md` として保存し、⟨完成条件⟩部分を空欄のテンプレにしておく（雛形は [templates/verify-prompt.md](../templates/verify-prompt.md)）。次に何か作るとき、これがあなたの「型」の第1号になる（スキル化の入口。★コラム5）
- 〔Eng〕**検証を自動にする**: 「完成条件3つを自動でチェックする簡単なテストを書いて、実行して結果を見せて」と指示する。人の目→Claudeの検証→自動テストという検証の3段活用。第9章「任せきる」の最小体験

## 10. 共有タイム（15分）

3〜4名にデモしてもらいます。見どころは作品そのものより**プロセス**です。発表者は次の3点を30秒ずつ:

1. 何を作ると決めたか（「詰めて」で固めた一言）
2. いちばん詰まった瞬間と、どの手で抜けたか
3. いちばん効いた指示（実際の文言を画面で見せる）

聞く側は「その指示、もらった」と思ったらメモしてください。**今日の最大のお土産は、他人の指示の語彙です。**

## 11. クロージング（10分）

### 今日やったこと

- 型（スキル）・計画・詰めの3原則でAIに情報を渡す
- 完成条件＋15分チェックポイントで**確実に**作りきる型
- 壊れても戻れるリカバリー3手

### 今日の先にある世界

今日のやり方には、まだ伸びしろが3段あります。

| 段階 | 何ができるようになるか | 入口 |
|---|---|---|
| **型を増やす** | 前編②で作った2つに続けて、検証手順など自分の作法を**スキル**にしていく | ★コラム5 |
| **仕様で導く** | 「詰めて」が残した用語集・決定・チケットを**仕様書**に育て、大きなものを計画的に作る | ★コラム6 |
| **任せきる** | 完了条件と検証を渡して、**自分が見ていない間に**作らせる（ゴール実行・自動ループ） | ★コラム7 |

今日「詰めて」で決めた完成条件とチケットは、実はそのまま「任せきる」ときの入力になります。**今日の型は、最先端の自律開発とひと続きです。**
