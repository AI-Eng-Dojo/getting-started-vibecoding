# 後半（2時間）自分で定義したIntentを、実際のソフトウェアにする

後半のゴール: **宿題で具体化した仕様を、レビュー→計画→実装→レビューという一本道で、検証済みのソフトウェアにして持ち帰ること。**

## 今日の全体地図

3パート構成の最後です。

```
前半 → 【宿題】 → 後半（今ここ）
```

- **前半（済）**: Vibe Codingを体験し、自分が作りたいものを言葉にし、その作法をGrill Me Skillとして保存した
- **宿題（済）**: そのSkillに自分のアイデアを問い詰めさせ、実装できるレベルまで仕様を具体化した
- **後半（今ここ）**: 具体化した仕様をレビューし、実装計画に落とし、実際にコードを書かせ、最後にレビュー・改善させる

前半と宿題の成果が、そのまま後半の入力になります。**宿題が思うように進まなかった人も後半は進められます**（→ 7. 宿題ふりかえり）。

## 7. 宿題ふりかえり（5分）

まず `/status` を叩いて、利用枠の残量といま選んでいるモデルを確認します。**残量が半分を切っている人は挙手してください。** このあと実装（10）に55分使うので、足りないことはここで分かったほうが手当てできます。

そのうえで、宿題で作った仕様（README）の状態を、自分の中で3段階のどれかに位置づけてください。

| 状態 | 目安 | このあとどうするか |
|---|---|---|
| **十分具体化できた** | 曖昧な言葉が残っておらず、機能が箇条書きで列挙できる | このまま8へ |
| **まだ曖昧さが残る** | 「使いやすく」のような、目で確認できない言葉が残っている | 8の冒頭でもう一段Grill Meする |
| **そもそも決まっていない** | 宿題に着手できなかった | 挙手してメンターと一緒に、前半2で作ったもの・ハンズオン②のREADMEを種に急いで種を固める |

**どの状態でも後半は進められます。** 焦って乗り換えず、今持っているものを育てる方向で進んでください。

## 8. ハンズオン⑤ 仕様レビュー（15分）

宿題の仕様を、Claude Codeと**もう一度**確認します。宿題は一人で進めたぶん、思い込みや飛躍が紛れ込んでいることがあります。

```text
これが今日実装する予定の仕様です。読んで、次を指摘してください。
- 曖昧で実装しづらい表現
- 抜けていそうな条件（データが消える・戻れないなど）
- 今日2時間では難しそうな範囲

指摘だけしてください。まだ直さないでください。
```

指摘が出たら、**自分の言葉で読み**、納得したものだけ反映させます。全部を鵜呑みにする必要はありません。「それは今日はやらない」と自分で判断してよい場面です。

```text
1と3を仕様に反映してください。2は今日は対象外にします。
```

### ✅ チェックポイント5

曖昧な言葉が残っていない状態の仕様（README）ができていること。

## 9. ハンズオン⑥ 実装計画（15分）

いきなりコードを書かせません。**仕様 → 実装計画**へ落とします。

```text
この仕様をもとに、実装計画を立ててください。
- どんな順序でタスクを分割するか
- 1つのタスクは15分以内で終わる大きさにしてください
- 各タスクで何を作るか
- 各タスクが終わったことを、画面のどこを見れば確認できるか
- 使う技術・構成（今日はブラウザで完結する構成を基本にしてください）
- 最初に着手すべきタスクはどれか、理由も添えて
```

出てきた計画に、明らかにやりすぎ（今日中に終わらない規模）が含まれていたら、ここで削ります。

```text
今日の2時間で終わる範囲に絞ってください。削るとしたらどのタスクからか、理由付きで提案してください。
```

### ✅ チェックポイント6

タスクの順序が並んだ実装計画ができていること。最初の1つが何かがはっきりしていること。

## 10. ハンズオン⑦ 実装（55分・メイン）

ここが後半の中心です。**全員同じアプリを作るのではなく、同じプロセスを使ってそれぞれ違うものを作ります。**

### 進め方

1. **最初のタスクから着手**: 9で決めた最初のタスクを、最小の形で作らせます（コピペ用テンプレ: [templates/first-instruction.md](../templates/first-instruction.md)）

```text
実装計画のタスク1だけを、最小の形で実装してください。
他のタスクにはまだ手をつけないでください。
```

2. **見て、直す**: できたら必ずブラウザで自分の目で確認します。違和感があれば、前半で覚えた作法どおり**2〜3個まとめて1回**で直させます
3. **15分ごとのチェックポイント運用**: 講師の合図（または自分のタイマー）で、次の3つを実行してください
   - **動いているか確認する** — ブラウザで自分の目で見る
   - **動いていれば保存する** — gitが分からなくても構いません。Claude Codeに「いまの状態をgitでコミットして保存してください」と頼めばやってくれます
   - **動いていなければ戻す** — 前半で覚えた**リカバリー3手**（貼る・戻す・小さくする）で動く状態に戻してから保存する

保存できたら次のタスクへ進みます。**動く状態のスナップショットが増えていくのが、この55分の正しい進み方です。**

### 詰まったときのエスカレーション順

1. リカバリー3手（貼る・戻す・小さくする）— まず自分で2回試す
2. 挙手 → メンターが巡回します
3. それでも詰まったら、仕様を削ってでも「動く状態」を優先する。**完成度より、確認できる状態を保つことが優先です**

### よくある状況と対処

| 状況 | 対処 |
|---|---|
| 最初のタスクが15分経っても動かない | 仕様が大きすぎるサイン。メンターと一緒にタスクをさらに小さく割る |
| 予定より早く全タスクが終わった | 11（レビュー・改善）を先取りして丁寧に行う。その後、仕様に無かった小さな改善を1つ足す |
| 途中でもっと良いアイデアを思いついた | **今日は乗り換えない。** メモして持ち帰る |
| 利用枠の上限に当たった | 挙手 → メンター機でペア作業に切り替え |

### ✅ チェックポイント7

実装計画のタスクのうち、**主要なものが動いている**状態で11へ。全タスクが揃っていなくても構いません。仕上げの時間で追い込みます。

### 🚀 拡張ミッション③（早く終わった人向け・任意）

- 〔共通〕**次の機能を1つ足す**: 仕様には無かった小さな改善を、今日の型（タスク化 → 最小実装 → 確認）でもう一周する
- 〔Eng〕**インフラ構成を設計させる**: 「このアプリをどこで動かし、データはどこに置くべきか」をClaudeに設計させ、選択理由を説明させる。実際にデプロイまでは今日はやりません
- 〔Eng〕**リリース自動化に挑戦する**: GitHubにpushしたら自動でチェックが走る、あるいは公開されるGitHub Actionsのワークフローを1本作らせてみる

## 11. ハンズオン⑧ レビュー・改善（20分）

動いたら終わりではありません。**その先の品質を、Claudeに点検・改善させます。**

### やらせること

前半で作ったSecurity Review Skillがあれば、ここで実戦投入します。無ければ、そのままプロンプトで代用して構いません（コピペ用テンプレ: [templates/verify-prompt.md](../templates/verify-prompt.md)）。

```text
実装したコードをレビューしてください。次を確認し、見つかった問題は直してください。
1. 簡単なテスト（動作確認できる範囲でよい）
2. セキュリティ上の問題（秘密情報の直書き、入力の未検証な使用など）
3. 読みにくい・重複しているコードのリファクタリング
4. 改善したほうがよい点の提案
5. 今日時間切れで残った場合、次に実装すべきことのリスト
```

> **「できました」を鵜呑みにしない。** Claudeは実際には確認せず「できています」と答えてしまうことがあります。最後は必ず**あなたの目**で動作を確認してください。あなたの確認が最終権限です。

### ✅ チェックポイント8（完成判定）

- [ ] 主要な機能が自分の目で動くことを確認した
- [ ] レビューで見つかった問題に一通り目を通した（すべて直せていなくてもよい）
- [ ] 次にやるべきことのリストがある

3つチェックが付いたら、それが今日の「完成」の定義です。

## 12. 成果共有（7分）

3〜4名にデモしてもらいます。見どころは作品そのものより**プロセス**です。発表者は次の4点を短く共有してください。

1. 何を作ったか
2. Claude Codeとどう相談したか
3. どんな指示が効いたか（実際の文言があれば見せる）
4. どこでAIが失敗したか、どう抜けたか

聞く側は「その指示、もらった」と思ったらメモしてください。**完成度を競う場ではなく、それぞれ違うものを同じプロセスで作った、という事実を確認する場です。**

## 13. クロージング（3分）

### 今日やったこと

```
Vibe Coding → Intentの明確化 → Skillによる拡張 → 仕様化 → 計画 → 実装 → Review
```

このハンズオン自体が、この一連の流れを体験する教材でした。前半で「ノリで作れてしまう」体験をし、その後「何を作りたいのかを明確にする」壁にぶつかり、Grill Me Skillでそれを乗り越え、後半でIntentを実際のソフトウェアに変換しました。
