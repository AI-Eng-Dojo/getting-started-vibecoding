# 前編（2時間）とにかく動くものを作る

前編のゴール: **バイブコーディングの回し方（見て、直す）を体で覚え、後編で作る自分のアイデアを「ゴールの一文」にすること。**

> 開始前の儀式: Claude Codeで `/status` と入力し、利用枠の残量を確認してください。
> 全員が満タン近くで始められているか、ここで揃えます。

---

## 1. オープニング（10分）

### バイブコーディングとは

コードを書く代わりに、**「こうしたい」を言葉で伝え、動くものを見て、また言葉で直す**開発のやり方です。
設計書も仕様書も書きません。あなたがやることは3つだけです。

1. 作りたいものを言う
2. 動いたものを**見る**
3. 見えた違和感を言う

「コードが読めないのに大丈夫?」— 大丈夫です。今日の判断基準はすべて**画面**にあります。コードを読んで判断する場面は一度もありません。

### 確実に作りきるための3原則

バイブコーディングは楽しい反面、ノリだけで進めると**高確率で迷子になります**。今日は迷子にならないための3原則を、進行そのものに埋め込んであります。

| 原則 | 意味 | 今日どこで使うか |
|---|---|---|
| **① ゴールは一文で** | 「誰が・何をすると・何が起きる」を一文で言えるものだけを作る | 前編5で書き、後編8の道しるべにする |
| **② 見て、直す** | 判断は画面で。違和感を言葉にして返す | ハンズオン②で練習 |
| **③ 動く状態を保つ** | 常に「動く状態」に戻れるようにしてから次に進む | 後編8の15分チェックポイント |

この3つさえ守れば、「気づいたら壊れていて、どこから直せばいいか分からない」は起きません。**確実にできあがる、の正体はテクニックではなくこの手順です。**

## 2. ライブデモ（10分）

講師がゼロから10分で1本作ります。手元では何もせず、次の3点だけ観察してください。

- [ ] 最初の指示が**どれくらい短いか**（完璧な指示は書いていない）
- [ ] 講師が**画面のどこを見て**、次に何と言ったか
- [ ] 「思ってたのと違う」ものが出たとき、**責めずに言い直している**こと

## 3. ハンズオン① 最初の成功体験（30分）

### やること

お題テンプレートから1つ選び、一発指示で試作品を動かします。

1. 事前準備で入手したこのリポジトリの [starters/](../starters/) から、選んだお題のフォルダをClaude Codeで開く
2. 下の3つから1つ選ぶ（迷ったらA。後編で作る自分のアイデアに近いものでもOK）
3. 指示文をそのまま貼り付けて実行（各お題フォルダのREADMEにも同じ指示文があります）
4. できあがったHTMLファイルをブラウザで開く

### お題A: ポモドーロタイマー → [starters/a-pomodoro-timer/](../starters/a-pomodoro-timer/)

```text
作業用のポモドーロタイマーを1つのHTMLファイルで作ってください。
25分の作業と5分の休憩を交互に繰り返し、残り時間が大きく表示され、
開始・一時停止・リセットのボタンがあり、時間が来たら音で知らせてください。
```

### お題B: 診断チャート → [starters/b-shindan-chart/](../starters/b-shindan-chart/)

```text
「あなたに合う旅行先診断」を1つのHTMLファイルで作ってください。
質問に5問答えると、回答の組み合わせからおすすめの旅行先タイプが表示されるようにしてください。
質問と結果の内容はあなたが考えてください。
```

### お題C: 習慣トラッカー → [starters/c-habit-tracker/](../starters/c-habit-tracker/)

```text
毎日の習慣を記録するトラッカーを1つのHTMLファイルで作ってください。
習慣を自由に登録でき、今日やったかどうかをチェックでき、
過去7日間の達成状況が一覧で見えるようにしてください。
データはブラウザを閉じても消えないようにしてください。
```

### 権限プロンプトについて（ここで1枚だけ）

実行中に「〜してもよいですか?」と聞かれます。これはClaude Codeの安全装置で、**ファイルの作成・変更やコマンドの実行は、必ずあなたの許可を取ってから**行われる仕組みです。今日の範囲では、表示された内容が「今いるフォルダの中のファイル操作」なら許可して構いません。詳しい仕組みは★コラム4へ（今は読まない）。

### ✅ チェックポイント1

選んだお題がブラウザで動いていること。**動いたら、中身に不満があってもそのまま次へ。** 直すのは次のハンズオンの仕事です。

### 🚀 拡張ミッション①（早く終わった人向け・任意）

> 拡張ミッションは全ハンズオン共通のルールです: **本線が終わった人だけ**が挑戦する。〔共通〕は誰でも、〔Eng〕はプログラミング経験者向け。やらなくても後編に一切影響しません。

- 〔共通〕**好みを覚えさせる**: プロジェクトのフォルダに `CLAUDE.md` というファイルを作り、「配色は落ち着いたトーン」「説明は短く」など自分の好みを3行書いて保存。そのうえで「見た目を作り直して」と指示し、好みが反映されるか確かめる（仕組みは★コラム3。書き方の例は [templates/CLAUDE.md.sample](../templates/CLAUDE.md.sample)）
- 〔Eng〕**履歴を持つ**: `git init` してここまでを最初のコミットにする。以降の変更で `git diff` を見れば、Claudeが何を変えたかを差分で追える。後編の15分チェックポイントをコミット運用に格上げできる

## 4. ハンズオン② 見て、直す（40分）

バイブコーディングの本体です。ここで覚えた回し方を、後編でそのまま自分のアイデアに使います。

### ステップ1: 違和感を3つ書き出す（5分）

さっき作ったものを1分触って、「思ってたのと違う」を**3つ**、メモに書き出してください。どんなに小さくてもOKです。

> 例:「ボタンが小さい」「色が事務的で楽しくない」「リセットしたら記録も消えて悲しい」

### ステップ2: まとめて1回で直させる（15分）

書き出した違和感を、**1回の指示にまとめて**伝えます。

```text
3点直してください。
1. スタートボタンをもっと大きく、押したくなる見た目に
2. 全体の配色を明るく楽しい雰囲気に
3. リセットしても通算の記録は消えないように
```

> **なぜ1つずつ言わないのか（今日いちばん大事な作法）**
> 違和感を1個ずつ投げると、やりとりの回数が増えて時間と利用枠を消耗するうえ、
> 全体の方向性が伝わらず「直したら別の場所が変になる」が起きやすくなります。
> **2〜3個まとめて1回**が、速くて、安くて、仕上がりも良い。今日はこのリズムで回します。

### ステップ3: 画像で直す（10分）

言葉にしにくい違和感は、**見たままを渡します**。

- 画面のスクリーンショットを撮り、Claude Codeに貼り付けて「この画面の、ここが窮屈に見えるので余白を増やして」
- 参考にしたいアプリやサイトのスクリーンショットを貼って「この雰囲気に寄せて」

### ステップ4: 壊してみる → リカバリー3手（10分）

ここで一度、**わざと欲張った指示**を出してみてください（例:「機能を5個一気に追加して」）。高確率で何かが壊れるか、思わぬ方向に進みます。そこで使うのがリカバリー3手です。

| 手 | いつ使う | どうやる |
|---|---|---|
| **① エラーをそのまま貼る** | 画面が真っ白・エラーが出た | エラーメッセージや画面のスクショを**説明せずそのまま**貼り、「動かなくなりました。直してください」 |
| **② ひとつ戻す** | 直る気配がない・どんどん悪化する | 「さっきの変更を取り消して、直前の動いていた状態に戻してください」。会話を巻き戻す機能やGitでも戻れます（★コラム参照） |
| **③ 小さく言い直す** | 欲張った指示が空中分解した | 5個頼んだなら「まず1個だけ」に分割してやり直す |

> 覚え方: **貼る・戻す・小さくする。** 詰まりの9割はこの3手で抜けられます。抜けられない残り1割のために、今日はメンターと救済タグがあります。

### ✅ チェックポイント2

自分の違和感が3つ以上反映され、壊れた状態から一度復帰できていること。

### 🚀 拡張ミッション②（早く終わった人向け・任意）

- 〔共通〕**雰囲気ごと寄せる**: 好きなアプリ・サイトのスクリーンショットを貼り、「情報はそのまま、この雰囲気に寄せて」と大改造させる。画像1枚が長文の説明に勝つ体験
- 〔Eng〕**作る前に計画だけ出させる**: プランモード（計画モード）に切り替えて、「このアプリに⟨大きめの機能⟩を足すとしたら?」と聞く。実装させず計画だけ読み、採用するか自分で判断する。「作らせる前に相談する」は後編8でそのまま効く
- 〔Eng〕**差分を読む**: 今日は「コードを読まない」が原則だが、例外として `git diff` だけ眺めてみる。まとめ指示1回でClaudeが何ファイル触るのか、規模感を掴んでおくと後編の指示の切り方が上手くなる

## 5. アイデアの言語化ワーク（20分）

後編で作る「自分のアイデア」を、原則①の形に落とします。**ここの精度が、後編の成功率をほぼ決めます。**
（書き込み用のテンプレートは [templates/goal-sheet.md](../templates/goal-sheet.md) にあります）

### ゴールの一文テンプレート

> **「⟨誰⟩が ⟨何をする⟩と ⟨何が起きる⟩」**

- 悪い例:「家計簿アプリ」（名詞だけ。何ができたら完成か分からない）
- 良い例:「**私が** レシートの金額を入力すると **今月あといくら使えるかが表示される**」

### 確認条件を3つ書く

ゴールの一文に対して、「これができていたら完成と言える」を3つ書きます。**あなたが操作して目で確認できること**だけを書いてください。

> 例（上の家計簿の場合）
> 1. 金額を入力して追加ボタンを押すと一覧に載る
> 2. 月の予算を設定でき、残額が自動計算される
> 3. ブラウザを閉じて開き直してもデータが残っている

### アイデアが浮かばない人へ: ゴールの一文サンプル10

そのまま使っても、改造してもOKです。

1. 私が今日の気分を選ぶと、気分に合った夕食の献立が提案される
2. 私が本のタイトルを登録すると、積読リストが「読みたい度」順に並ぶ
3. 家族がやった家事をタップすると、今週の家事分担の偏りがグラフで見える
4. 私が会議名と時間を入れると、会議コストが金額で表示される
5. 私が今日の一行日記を書くと、過去の同じ日の日記が一緒に表示される
6. 私が旅行の候補地を登録すると、メンバーの投票で行き先が決まる
7. 私が薬を飲んだボタンを押すと、飲み忘れの有無がカレンダーで見える
8. 私が英単語を登録すると、忘れた頃にクイズとして出題される
9. 私が推しの配信予定を登録すると、今日の予定がカウントダウン表示される
10. 私が冷蔵庫にある食材を入れると、作れる料理の候補が出てくる

### ✅ チェックポイント3（提出）

「ゴールの一文＋確認条件3つ」を付箋（またはフォーム）に書いて提出。メンターが休憩中に全員分に目を通し、危ないもの（大きすぎる・確認できない）には休憩明けに一声かけます。
