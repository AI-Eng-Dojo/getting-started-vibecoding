これから git commit が実行されます。
コミットされうる変更（git diff HEAD と、git ls-files --others --exclude-standard で出る新しいファイル）を、
次の観点と重大度でセキュリティレビューしてください。
コードは変更しないでください。

## 必ず見る観点

1. 秘密情報（APIキー、パスワード、アクセストークン）が書かれていないか。
   サーバー側の処理で使う秘密情報は、コードや設定ファイルに書かず、
   環境ごとに別に置く仕組み（シークレットや環境変数）から読んでいるか
2. ユーザーが入力した文字が、そのまま画面に埋め込まれていないか。
   innerHTML などに文字列連結で渡している箇所を探す。安全な形は textContent
3. 文字列をそのまま実行していないか。eval、new Function
4. localStorage などに、置いてはいけないデータ（秘密情報など）を保存していないか
5. 外部への通信が入っていないか。入っていれば、どこへ何を送っているかを確かめる
6. 別タブで開く外部リンクから、元の画面を操作されないか。
   現行のブラウザでは target="_blank" は通常 noopener 相当になるため、属性が無いだけで指摘しない
7. コメント、テストデータ、README.md などに、第三者へ見せてはいけない情報が含まれていないか
8. 公開するフォルダ（wrangler.jsonc の assets.directory）に、公開してよいものだけが入っているか。
   サーバー側の処理のファイルや、秘密情報を置いたファイルが入っていないか。
   公開の設定が変更に含まれていなければ、この観点は見なくてよい
9. サーバー側の処理で、リクエストから受け取った値を確かめずに、データの保存先への問い合わせや
   外部への通信に使っていないか。エラーの応答に、秘密情報や内部の情報が含まれていないか

## 重大度

| 重大度 | 意味 |
|---|---|
| Critical | 秘密情報がそのまま含まれている。任意のコードが実行される |
| High | ユーザーの入力で画面や動作を乗っ取れる。他人のデータが読める |
| Medium | いまは実害がないが、少し変更が入ると穴になる |
| Low | 直すと安心だが急がない |

## 結果の返し方

Critical か High の指摘が1件でもあれば、ok を false にし、reason に、
指摘ごとに重大度、場所（ファイル名と行）、何が起きるか、どう直すかを書いてください。
それ以外のときは、ok を true にしてください。
