# Claude Codeで作りたいものが確実にできあがる バイブコーディング実践入門

Claude Codeに言葉で実装を頼み、動いたものを自分で触って確かめ、違和感やエラーを伝えて直すハンズオンワークショップです。
前半は小さなアプリでこの繰り返しを体験し、自分のアイデアでも、試作で気づいたことを仕様に戻しながら進めます。
**バイブコーディング = Intent（何を作りたいのか）の明確化 → エージェントスキルによる緻密化 → 仕様化 → 計画 → 実装 → レビュー → 公開** まで、前半・後半（間に宿題1日）を通じて実現します。

> 📖 **教材はWebサイトでも読めます → <https://ai-eng-dojo.github.io/getting-started-vibecoding/>**

## 対象者

- IT・システム開発経験のあるエンジニア
- 経営者、スタートアップ志望者などのノンテク層

技術レベルに関係なく、Claude Codeを使って**バイブコーディングを体験できます**。**コードを書く必要はありません。**

> 後半のレビューでは、コードの書き方についての指摘も出てきます。**読めなくても判断できる目安を用意してある**ので、ご安心ください。

進みの速い人向けには、各ハンズオンに **🚀拡張ミッション**（任意）を用意しています。

4つ目が今日の本命です。宿題を挟んで、前半の「ノリで動いた」体験と後半の「狙って作りきる」体験を、自分の手でつなぎます。

## このワークショップで持ち帰れるもの

- **頭の中のアイデアが、AIとの対話を経て明文化され、動くソフトウェアになり、URLで人に見せられる状態**
- 「何を作りたいか」を自分から引き出す**壁打ちの作法**
- 自分の作法を**エージェントスキルとして保存し、一言で呼び出せる**状態
- Claudeが判断して呼び出すエージェントスキルと、条件に合えば確実に動くHooksで、開発工程そのものを拡張していくという考え方（Grill Me以外にも広げられる地図）
- 仕様 → 計画 → 実装 → レビュー → 公開という、迷子にならずに作りきるための一本道
- 画面での完成判定、同梱の `/code-review`、セキュリティレビューを分け、指摘から直すものを選ぶ進め方

### 【宿題】（前半と後半の間・1日以上）

参加者それぞれが、**後半で実装するもの**を決めます。そして自作したGrill Me系エージェントスキルを使って、自分のアイデアをClaude Codeに徹底的に質問させ、後半で実装できるレベルまで仕様を具体化します。

宿題の成果物は、**仕様（`README.md`）とやることリスト（`TASKS.md`）の2ファイル**です。自作した `tsumete` を一周させ、確定した用語や決定があれば `CONTEXT.md`（用語集）や決定記録も残します。前提として、**ブラウザだけで動く構成・ログインや外部サービス連携なし・後半の実装時間で作りきれる規模**まで削ってもらいます。この前提は会話で毎回伝えるのではなく、`myapp` に置く `CLAUDE.md` に書いておきます（[前半3で配置し、6で再確認](docs/01-part1.md)）。
宿題まではローカルでコミットし、GitHubへの最初のプッシュは後半10のセキュリティレビュー後に行います。

## この講座で見せたい「変化」

このハンズオン自体が、**「ノリで作れる」体験から出発して、作りたいものが確実にできあがるバイブコーディングへ育てていく**教材です。

前半ではまず「ノリで作れてしまう」というバイブコーディングの強烈な体験をさせ、その後で「もっとちゃんと作ろうとすると、何を作りたいのかを明確にする必要が出てくる」という壁に参加者自身をぶつけます。そこでGrill Me系エージェントスキルが登場し、曖昧なIntentをAIとの対話によって仕様へ変換します。

```
バイブコーディング = Intent（何を作りたいのか）の明確化 → エージェントスキルによる緻密化 → 仕様化 → 計画 → 実装 → レビュー → 公開
```

### 公開サイトについて

この教材は、`main` に入るたびGitHub Actionsが [MkDocs](https://www.mkdocs.org/) でHTML化し、<https://ai-eng-dojo.github.io/getting-started-vibecoding/> に自動で公開されます。Markdown側のリンクは書き換えていないので、**GitHub上の表示とサイト上の表示のどちらからでも同じようにたどれます。**

手元で見た目を確認したいときは、次の1コマンドで `http://127.0.0.1:8000` にプレビューが立ちます。

```bash
uv run --with-requirements requirements-site.txt python .github/scripts/build-site.py --serve
```

公開と同じビルドとリンク検査は次のコマンドで確認できます。

```bash
uv run --with-requirements requirements-site.txt python .github/scripts/build-site.py
python3 .github/scripts/check-site-links.py
```

`instructor/` と各お題の `rescue/`（救済版）は、サイトには載せていません（リポジトリ上には残っています）。救済版は「開いてコードをコピーする」手順なので、HTMLとして動いてしまうサイト側に置くと手順が成立しないためです。配布は `raw.githubusercontent.com` のURLが担当しています。

見た目は [academy.claude.com](https://academy.claude.com/) の配色・組版に合わせてあります（`site-theme/anthropic.css`）。Anthropicの専用フォントは配布されていないため、Google Fontsの近縁で代替しています。ロゴ・ワードマークは使っていません。
