# Claude Codeで作りたいものが確実にできあがる バイブコーディング実践入門

Claude Codeを使って、あなたのアイデアをソフトウェアに変換する体験をするハンズオンワークショップです。
**Vibe Coding → Intentの明確化 → Skillによる拡張 → 仕様化 → 計画 → 実装 → レビュー** まで、前半・後半（間に宿題1日）を通じて一本道でたどります。

これは「プログラミングを教える講座」ではありません。**AIと一緒にアイデアをソフトウェアへ変換する体験**そのものが目的です。

## 対象者

20名程度を想定しています。

- 約10名: IT・システム開発経験のあるエンジニア
- 約10名: 経営者、スタートアップ志望者などのノンテク層

技術レベルが大きく異なる参加者が、全員Claude Codeを使って**同じ基本プロセス**を体験します。**コードを書く必要はありません。** あなたがやることは、指示を出す・出てきたものを見る・レビューして直させる、の3つです。

> 後半のレビューでは、コードの書き方についての指摘も出てきます。**読めなくても判断できる目安を用意してある**ので、そのまま進めます。

進みの速い人向けには、各ハンズオンに **🚀拡張ミッション**（任意）を用意します。**どこまでやっても、持ち帰るものは同じ「型」です。**

4つ目が今日の本命です。宿題を挟んで、前半の「ノリで動いた」体験と後半の「狙って作りきる」体験を、自分の手でつなぎます。

## このワークショップで持ち帰れるもの

- **頭の中のアイデアが、AIとの対話を経て明文化され、動くソフトウェアになり、URLで人に見せられる状態**
- 「何を作りたいか」を自分から引き出す**壁打ちの作法**
- 自分の作法を**Skillとして保存し、どのプロジェクトでも呼び出せる**状態
- SkillとHooksで開発工程そのものを拡張していくという考え方（Grill Me以外にも広げられる地図。Skillは判断を介する、Hooksは確実に動く）
- 仕様 → 計画 → 実装 → レビュー → 公開という、迷子にならずに作りきるための一本道
- 開発工程そのものをスキルに分けて噛み合わせる型（`tdd`・`code-review`・`security-review`。**1枚に全部入れると報告が混ざって何も見えなくなる**）

## 全体の流れ

事前準備 → **前半3時間** → 【宿題】 → **後半2時間55分**、という3パート構成です。前半と後半の間に1日以上の宿題期間を置きます。

### 【宿題】（前半と後半の間・1日以上）

参加者それぞれが、**後半で実装するもの**を決めます。そして自作したGrill Me Skillを使って、自分のアイデアをClaude Codeに徹底的に質問させ、後半で実装できるレベルまで仕様を具体化します。

宿題の成果物は、**仕様（`README.md`）とやることリスト（`TASKS.md`）の2ファイル**です。自作した `tsumete` を一周させると、詰めた過程で `CONTEXT.md`（用語集）や決定記録も残ります。前提として、**ブラウザだけで動く構成・ログインや外部サービス連携なし・後半の実装70分で作りきれる規模**まで削ってもらいます（詳細は [docs/01-part1.md](docs/01-part1.md) の6章）。

## この講座で見せたい「変化」

このハンズオン自体が、**「Vibe Codingから仕様駆動開発へどう移行するのか」**を体験する教材です。

前半ではまず「ノリで作れてしまう」というVibe Codingの強烈な体験をさせ、その後で「もっとちゃんと作ろうとすると、何を作りたいのかを明確にする必要が出てくる」という壁に参加者自身をぶつけます。そこでGrill Me Skillが登場し、曖昧なIntentをAIとの対話によって仕様へ変換します。

```
Vibe Coding → Intentの明確化 → Skillによる拡張 → 仕様化 → 計画 → 実装 → Review → デプロイ
```

- 参加者は **README → docs/00-prep.md → 当日は docs/01-part1.md と docs/02-part2.md** の順に読み進めます
- 前半2でVibe Codingを行うのは**教材リポジトリではなく、その場で作る `vibecoding-0908` 側**です。`starters/` の3種は、お題に迷ったとき・自由に作ってみて手応えがなかったときの代替お題です

- 詰まったとき用の「救済版」（starters/の各お題の完成状態。`starters/⟨題⟩/rescue/index.html`）の使い方は [starters/README.md](starters/README.md) を参照してください
- 独自ドメイン・リリース自動化（GitHub Actions）といった発展的な内容は、本線には含めず🚀拡張ミッションおよび [docs/columns.md](docs/columns.md) 側で扱います
