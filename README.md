# Claude Codeで作りたいものが確実にできあがる バイブコーディング実践入門

Claude Codeを使って、あなたのアイデアをソフトウェアとして実現するためのハンズオンワークショップです。
**バイブコーディング = Intentの明確化 → Skillによる緻密化 → 仕様化 → 計画 → 実装 → レビュー** まで、前半・後半（間に宿題1日）を通じて実現します。

> 📖 **教材はWebサイトでも読めます → <https://ai-eng-dojo.github.io/getting-started-vibecoding/>**

## 対象者

- IT・システム開発経験のあるエンジニア
- 経営者、スタートアップ志望者などのノンテク層

技術レベルに関係なく、Claude Codeを使って**バイブコーディングを体験できます**。**コードを書く必要はありません。**

> 後半のレビューでは、コードの書き方についての指摘も出てきます。**読めなくても判断できる目安を用意してある**ので、ご安心ください。

進みの速い人向けには、各ハンズオンに **🚀拡張ミッション**（任意）を用意しています。

## 成果物

| # | 成果物 | 格納場所 |
|---|---|---|
| 1 | バイブコーディングで動かしたデモアプリ | `vibecoding-0908` 内のソースコード |
| 2 | 言語化された**自分のアイデア** | `myapp` 内のREADME |
| 3 | 自作の**Grillスキル/コードレビュー/セキュリティレビュースキル** | `myapp` 内の各 `SKILL.md` ファイル |
| 4 | **自分のアイデアのアプリ一式** | 仕様（`README.md`）・やることリスト（`TASKS.md`）・実装・レビュー結果・**公開URL** |

4つ目が今日の本命です。宿題を挟んで、前半の「ノリで動いた」体験と後半の「狙って作りきる」体験を、自分の手でつなぎます。

## このワークショップで持ち帰れるもの

- **頭の中のアイデアが、AIとの対話を経て明文化され、動くソフトウェアになり、URLで人に見せられる状態**
- 「何を作りたいか」を自分から引き出す**壁打ちの作法**
- 自分の作法を**Skillとして保存し、どのプロジェクトでも呼び出せる**状態
- SkillとHooksで開発工程そのものを拡張していくという考え方（Grill Me以外にも広げられる地図。Skillは判断を介する、Hooksは確実に動く）
- 仕様 → 計画 → 実装 → レビュー → 公開という、迷子にならずに作りきるための一本道
- 開発工程そのものをスキルに分けて噛み合わせる型（`tdd`・`code-review`・`security-review`。**1枚に全部入れると報告が混ざって何も見えなくなる**）

## 当日扱う場所は3つ

| 場所 | 役割 |
|---|---|
| **教材リポジトリ**（このリポジトリ） | 講義資料・手順・サンプルを公開しておく場所。**cloneせず、ブラウザや画面共有で見るだけ**です |
| **`vibecoding-0908`** | 前半2で作る使い捨てのリポジトリ。**その場でClaude Codeに頼んで新規作成・clone**します。前半2が終われば役目は終わりです |
| **`myapp`** | ハンズオン②で作るリポジトリ。**ここから宿題・後半まで、1日通してずっとこのリポジトリを使います。** README・TASKS・実装・PRまで、すべてこのリポジトリのルートで行います |

教材リポジトリはfork・cloneのどちらも不要です。`vibecoding-0908`・`myapp` はどちらも各自のGitHubアカウントに新規作成する**自分だけのリポジトリ**なので、他の参加者と衝突する心配がありません。

## 全体の流れ

事前準備 → **前半3時間** → 【宿題】 → **後半2時間55分**、という3パート構成です。前半と後半の間に1日以上の宿題期間を置きます。

### 事前準備（前日まで・セルフペース）→ [docs/00-prep.md](docs/00-prep.md)

Claude Code／GitHub／VS Code／GitHub CLI（`gh` コマンド）のセットアップと、動作確認ミッションです。リポジトリ自体は当日その場で作るため、事前準備では作成しません。

### 前半（3時間）Claude Codeの基礎を身につけ、作りたいものをAIと一緒に具体化する → [docs/01-part1.md](docs/01-part1.md)

| 時間（案） | 内容 | この枠の成果物 |
|---|---|---|
| 0:00–0:10 | **1. オープニング** — バイブコーディングとは／今日の予定／Claude Codeの仕組み（モデル・ツール・コンテキスト・権限）／最初に叩く6つのコマンド | — |
| 0:10–1:15 | **2. ハンズオン① Claude Code基礎** — `vibecoding-0908` を作り、バイブコーディング→MCP→エージェントスキルの3本柱を一通り触り、設定を開いて中を見る | 動くアプリ1個以上・Gmail下書き1通・`tsumete`(プロジェクトレベル) |
| 1:15–2:00 | **3. ハンズオン② 自分が作りたいアプリを考える** — 自分のアプリ用リポジトリ `myapp` を作り、何を／誰が／何ができればいいか／どんな体験にしたいかを言語化する。`tsumete` をユーザーレベルに置き直す | `myapp` リポジトリ・Intentを書いたREADME・ユーザーレベルの `tsumete` |
| 2:00–2:35 | **4. ハンズオン③ Grill Me系エージェントスキルを自作する** — `tsumete` を育てながら `tsumetsume`・`ddd` に役割を分ける | `SKILL.md` 3ファイル |
| 2:35–2:55 | **5. ハンズオン④ SkillとHooksで開発工程を拡張する** — Skillで工程を拡張する考え方とHooksに触れる | Hook 1件 |
| 2:55–3:00 | **6. 前半まとめ・宿題の説明** | — |

**2の狙いは完成度ではありません。** あえて仕様を厳密にしすぎず、「頼んだら本当にソフトウェアができた」という体験を先に作ります。

**3〜4が前半の核心です。** 既存のSkillを使わせるのではなく、**自分でGrill Me Skillを作る**ことで、エージェントスキルとは何か・AIの振る舞いをどう設計するか・毎回書くプロンプトとSkill化することの違いを実体験として理解します。

### 【宿題】（前半と後半の間・1日以上）

参加者それぞれが、**後半で実装するもの**を決めます。そして自作したGrill Me Skillを使って、自分のアイデアをClaude Codeに徹底的に質問させ、後半で実装できるレベルまで仕様を具体化します。

宿題の成果物は、**仕様（`README.md`）とやることリスト（`TASKS.md`）の2ファイル**です。自作した `tsumete` を一周させると、詰めた過程で `CONTEXT.md`（用語集）や決定記録も残ります。前提として、**ブラウザだけで動く構成・ログインや外部サービス連携なし・後半の実装70分で作りきれる規模**まで削ってもらいます（詳細は [docs/01-part1.md](docs/01-part1.md) の6章）。

### 後半（2時間55分）自分で定義したIntentを、動いて・公開されたソフトウェアにする → [docs/02-part2.md](docs/02-part2.md)

| 時間（案） | 内容 | この枠の成果物 |
|---|---|---|
| 0:00–0:05 | **7. 宿題ふりかえり** — 手元にあるものを3段階で確認 | — |
| 0:05–0:20 | **8. ハンズオン⑤ 今日やる分を決める** — `TASKS.md` の粒度を揃え、MVPに絞り込む | MVPに絞った `TASKS.md` |
| 0:20–1:30 | **9. ハンズオン⑥ 実装**（メイン） — `tdd` スキルで1件ずつ。15分ごとに動く状態を保存する | 動くアプリ本体 |
| 1:30–2:07 | **10. ハンズオン⑦ レビューを仕組みにする** — 2軸レビュー・セキュリティレビュー・Hooksで「必ず通る」状態にする | レビュー結果・修正・Hook 2件 |
| 2:07–2:27 | **11. ハンズオン⑧ Cloudflareに公開する** — 自分のPCの中から、URLで見られる場所へ | 公開URL |

| 2:42–2:49 | **13. 成果共有** — 何を作ったか／どう相談したか／どこでAIが失敗したか | — |
| 2:49–2:55 | **14. クロージング** — つないだものの外し方・持ち帰るもの | — |

重要なのは「全員同じアプリを作る」のではなく、**同じ開発プロセスを使って、それぞれ違うものを作る**ことです。前半5で触れた「SkillとHooksの違い」は、10のセキュリティレビュー＋Hookでそのまま実戦投入します。**開発の計画は最初から最後まで `TASKS.md` で管理し、11のCloudflare・12のNotion／Backlogはそれを置き換えません。**

時間（案）は現時点の目安です。開催が近づき進行が固まった段階で確定させます。

## この講座で見せたい「変化」

このハンズオン自体が、**「バイブコーディングから仕様駆動開発へどう移行するのか」**を体験する教材です。

前半ではまず「ノリで作れてしまう」というバイブコーディングの強烈な体験をさせ、その後で「もっとちゃんと作ろうとすると、何を作りたいのかを明確にする必要が出てくる」という壁に参加者自身をぶつけます。そこでGrill Me Skillが登場し、曖昧なIntentをAIとの対話によって仕様へ変換します。

```
バイブコーディング → Intentの明確化 → Skillによる拡張 → 仕様化 → 計画 → 実装 → レビュー → デプロイ
```

### 公開サイトについて

この教材は、`main` に入るたびGitHub Actionsが [MkDocs](https://www.mkdocs.org/) でHTML化し、<https://ai-eng-dojo.github.io/getting-started-vibecoding/> に自動で公開されます。Markdown側のリンクは書き換えていないので、**GitHub上の表示とサイト上の表示のどちらからでも同じようにたどれます。**

手元で見た目を確認したいときは、次の1コマンドで `http://127.0.0.1:8000` にプレビューが立ちます。

```bash
uv run --with-requirements requirements-site.txt python .github/scripts/build-site.py --serve
```

`instructor/` と各お題の `rescue/`（救済版）は、サイトには載せていません（リポジトリ上には残っています）。救済版は「開いてコードをコピーする」手順なので、HTMLとして動いてしまうサイト側に置くと手順が成立しないためです。配布は `raw.githubusercontent.com` のURLが担当しています。

見た目は [academy.claude.com](https://academy.claude.com/) の配色・組版に合わせてあります（`site-theme/anthropic.css`）。Anthropicの専用フォントは配布されていないため、Google Fontsの近縁で代替しています。ロゴ・ワードマークは使っていません。
