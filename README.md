# Claude Codeで作りたいものが確実にできあがる バイブコーディング実践入門

Claude Codeを使って、あなたのアイデアをソフトウェアに変換する体験をするハンズオンワークショップです。
**Vibe Coding → Intentの明確化 → Skillによる拡張 → 仕様化 → 計画 → 実装 → レビュー** まで、前半・後半（間に宿題1日）を通じて一本道でたどります。

これは「プログラミングを教える講座」ではありません。**AIと一緒にアイデアをソフトウェアへ変換する体験**そのものが目的です。

## 対象者

20名程度を想定しています。

- 約10名: IT・システム開発経験のあるエンジニア
- 約10名: 経営者、スタートアップ志望者などのノンテク層

技術レベルが大きく異なる参加者が、全員Claude Codeを使って**同じ基本プロセス**を体験します。**コードを書く必要はありません。** あなたがやることは、指示を出す・出てきたものを見る・レビューして直させる、の3つです。

進みの速い人向けには、各ハンズオンに **🚀拡張ミッション**（任意）を用意します。**どこまでやっても、持ち帰るものは同じ「型」です。**

|---|---|---|---|

4つ目が今日の本命です。宿題を挟んで、前半の「ノリで動いた」体験と後半の「狙って作りきる」体験を、自分の手でつなぎます。

## このワークショップで持ち帰れるもの

- **頭の中のアイデアが、AIとの対話を経て明文化され、動くソフトウェアになっている状態**
- 「何を作りたいか」を自分から引き出す**壁打ちの作法**
- 自分の作法を**Skillとして保存し、どのプロジェクトでも呼び出せる**状態
- SkillとHooksで開発工程そのものを拡張していくという考え方（Grill Me以外にも広げられる地図。Skillは判断を介する、Hooksは確実に動く）
- 仕様 → 計画 → 実装 → レビューという、迷子にならずに作りきるための一本道

## リポジトリは2種類

| リポジトリ | 役割 |
|---|---|
| **教材リポジトリ**（このリポジトリ） | 講義資料・手順・サンプルを公開しておく場所。参加者は読むだけでよく、書き込みません |

## 全体の流れ

事前準備 → **前半2時間** → 【宿題】 → **後半2時間**、という3パート構成です。前半と後半の間に1日以上の宿題期間を置きます。

### 事前準備（前日まで・セルフペース）→ [docs/00-prep.md](docs/00-prep.md)

Claude Code／GitHub／VS Codeのセットアップと、2つのリポジトリの取得、動作確認ミッションです。

### 前半（2時間）Vibe Codingを体験し、自分の意図をAIに伝える方法へ進む → [docs/01-part1.md](docs/01-part1.md)

| 時間（案） | 内容 | この枠の成果物 |
|---|---|---|
| 0:00–0:10 | **1. オープニング** — バイブコーディングとは／今日の全体地図／最初に叩く3つのコマンド | — |
| 0:10–0:35 | **2. ハンズオン① Claude Codeを触る** — 実践用リポジトリで簡単なものを1個作る。権限プロンプトと設定の確認まで | 動くアプリ1個以上 |
| 0:35–1:00 | **3. ハンズオン② 自分が作りたいものを考える** — 何を／誰が／何ができればいいか／どんな体験にしたいかを言語化する | Intentを書いたREADME |
| 1:00–1:40 | **4. ハンズオン③ Grill Me系Agent Skillを自作する** — `tsumetsume`・`ddd`・`tsumete` の3つに分けて自分で作る | `SKILL.md` 3ファイル |
| 1:40–1:55 | **5. ハンズオン④ SkillとHooksで開発工程を拡張する** — Skillで工程を拡張する考え方とHooksに触れる | 候補SkillのメモとHook 1件 |
| 1:55–2:00 | **6. 前半まとめ・宿題の説明** | — |

**2の狙いは完成度ではありません。** あえて仕様を厳密にしすぎず、「頼んだら本当にソフトウェアができた」という体験を先に作ります。

**3〜4が前半の核心です。** 既存のSkillを使わせるのではなく、**自分でGrill Me Skillを作る**ことで、Agent Skillとは何か・AIの振る舞いをどう設計するか・毎回書くプロンプトとSkill化することの違いを実体験として理解します。

### 【宿題】（前半と後半の間・1日以上）

参加者それぞれが、**後半で実装するもの**を決めます。そして自作したGrill Me Skillを使って、自分のアイデアをClaude Codeに徹底的に質問させ、後半で実装できるレベルまで仕様を具体化します。

宿題の成果物は、**仕様（`README.md`）とやることリスト（`TASKS.md`）の2ファイル**です。自作した `tsumete` を一周させると、詰めた過程で `CONTEXT.md`（用語集）や決定記録も残ります。前提として、**ブラウザだけで動く構成・ログインや外部サービス連携なし・後半2時間で作りきれる規模**まで削ってもらいます（詳細は [docs/01-part1.md](docs/01-part1.md) の6章）。

重要なのは「全員同じアプリを作る」のではなく、**同じ開発プロセスを使って、それぞれ違うものを作る**ことです。前半で作ったSecurity Review Skillは、10でそのまま実戦投入します。

時間（案）は現時点の目安です。開催が近づき進行が固まった段階で確定させます。

## この講座で見せたい「変化」

このハンズオン自体が、**「Vibe Codingから仕様駆動開発へどう移行するのか」**を体験する教材です。

前半ではまず「ノリで作れてしまう」というVibe Codingの強烈な体験をさせ、その後で「もっとちゃんと作ろうとすると、何を作りたいのかを明確にする必要が出てくる」という壁に参加者自身をぶつけます。そこでGrill Me Skillが登場し、曖昧なIntentをAIとの対話によって仕様へ変換します。

```
Vibe Coding → Intentの明確化 → Skillによる拡張 → 仕様化 → 計画 → 実装 → Review
```

```
getting-started-vibecoding/       ← 教材リポジトリ（このリポジトリ）
├── README.md              ← いまここ（入口）
├── docs/                  参加者用テキスト
│   ├── 00-prep.md         事前準備ガイド（前日までに完了）
│   ├── 01-part1.md        前半テキスト
│   ├── 02-part2.md        後半テキスト
│   └── columns.md         ★後読みコラム集（当日は読まない。帰りの電車で）
├── starters/              前半2の代替お題テンプレート3種（任意）
│   ├── a-pomodoro-timer/  お題A: ポモドーロタイマー
│   ├── b-shindan-chart/   お題B: 診断チャート
│   └── c-habit-tracker/   お題C: 習慣トラッカー
├── skills/                前半4〜5で作るSkillの完成例（答え合わせ用。まずは見ないで作る）
├── templates/             コピペして使うテンプレート（持ち帰り素材）
├── demos/                 ライブデモのソース・参考実装置き場
└── instructor/            講師・メンター用（参加者は読まなくてOK）
```

- 参加者は **README → docs/00-prep.md → 当日は docs/01-part1.md と docs/02-part2.md** の順に読み進めます
- 前半2でVibe Codingを行うのは**教材リポジトリではなく実践用リポジトリ側**です。`starters/` の3種は、お題に迷ったとき・自由に作ってみて手応えがなかったときの代替お題です
- `skills/` は前半4〜5で作るSkillの**完成例**です。自分で書くのが本線なので、**まずは見ないで作ってください。** 詰まったとき・答え合わせのときに開きます
- 詰まったとき用の「救済タグ」（starters/の各お題の完成状態）の使い方は [starters/README.md](starters/README.md) を参照してください
- インフラ構成の設計・リリース自動化（GitHub Actions）といった発展的な内容は、本線には含めず🚀拡張ミッションおよび [docs/columns.md](docs/columns.md) 側で扱います
